### 여러 문서를 합친 시간순 업무표
id: wk-timeline
meta: 시행계획·설명서·요강처럼 문서가 여러 개일 때. 문서 간 차이를 따로 짚게 합니다
```
[시작 월]부터 [끝 월]까지 [담당자1]과 [담당자2]가 해야 할 [업무 이름] 업무를 시간 순서로 정리해 줘. [문서1], [문서2], [문서3]을 모두 확인해서 날짜가 있는 일은 날짜를 꼭 넣어 줘.
표는 [일자 | 누가 | 업무 내용 | 서식 번호 | 제출처]로 만들고, 표 아래에 '문서끼리 다른 부분'을 따로 정리해 줘.
```

### 채팅 설정 → 맞춤: 업무 비서 지침
id: wk-chat-setting
meta: ⋮ → 채팅 설정 → [맞춤]에 붙여 넣기. 이 노트북을 쓰는 모든 사람에게 적용됩니다
check: 실습이 끝나면 [기본값]으로 되돌리거나 업무 노트북에만 쓰세요.
```
#역할: 너는 [학교 이름] [학년] [업무 이름] 업무를 돕는 '업무 비서'야. 담임교사와 학년부장이 묻는 것에 답해.
#규칙
- 답은 항상 '결론 한 줄 → 해야 할 일(누가·언제까지) → 근거'의 순서로 써.
- 날짜·서식 번호·제출처는 반드시 소스에서 인용하고, 소스에 없으면 '소스에 없음, [확인할 곳] 확인 필요'라고 말해.
- 문서끼리 내용이 다르면 둘 다 보여 주고 어느 쪽이 최신인지 표시해.
- 학생 이름·주민등록번호 같은 개인정보는 받지도 쓰지도 마.
#형식: 할 일은 표로, 학부모 안내가 필요하면 마지막에 '학부모 안내 문장' 2~3줄을 덧붙여.
```

### 까다로운 부장교사의 계획서 점검
id: wk-bujang
meta: 내가 쓴 계획서(HWPX·PDF)와 매뉴얼을 함께 넣고 결재 전에 셀프 점검
check: "대답할 수 없습니다"가 뜨면 일시 오류입니다. 같은 프롬프트를 다시 보내세요.
```
#역할: 너는 [매뉴얼 이름]을 꿰고 있는 까다로운 20년 차 부장교사야.
#명령: 소스의 '[내 계획서 이름]'을 [매뉴얼 이름]과 비교해서, 잘못되었거나 빠진 부분을 찾아 고쳐 줘.
#맥락
##점검 기준: [기준1], [기준2], [기준3], [기준4]
##조건: 지적마다 계획안의 해당 부분과 매뉴얼 근거를 함께 인용해 줘. 매뉴얼에 근거가 없으면 '매뉴얼에 없음'이라고 표시해 줘.
##말투: 깐깐하게 지적하되, 고칠 방향은 친절하게.
#형식: 표(점검 항목 | 계획안 내용 | 매뉴얼 기준 | 문제점 | 고친 문장)로 정리하고, 마지막에 '결재 전에 꼭 고칠 3가지'를 번호로 적어 줘.
```

### 좋은 답을 소스로 쌓기
id: wk-note-source
meta: 프롬프트가 아니라 순서입니다. 메모에 저장 → 소스로 변환 → 이름 앞에 '!'
```
1) 답 아래 [메모에 저장]
2) 스튜디오의 메모를 열고 [소스로 변환]
3) 소스 ⋮ → 소스 이름 바꾸기 → '![내가 붙일 이름]'
→ '!'로 시작하는 소스는 목록 맨 위로 올라와 원본과 구분됩니다.
```
