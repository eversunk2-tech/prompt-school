id: ds-web-compare

check: AI는 학년 수준은 보지만 교육과정 시기(예: 2015 개정 6-1 자료)는 놓칠 수 있습니다. 미리보기에서 직접 확인하세요.
```
[확장]으로 시작하는 웹 소스들을 [기준] 지도서와 비교해 줘. ① 지도서와 설명이나 용어가 다른 부분 ② [학년] 수준을 넘는 내용 ③ 수업에 바로 쓸 만한 사례·통계를 표(웹 소스 이름 | 내용 | 지도서 근거 | 판단)로 정리하고, 근거 인용을 달아 줘.
```


### 백워드 1단계: 바라는 결과

check: 성취기준 코드와 문장을 인용 번호를 눌러 지도서와 대조하세요.
```
#역할: 너는 백워드 설계(이해 중심 교육과정)에 밝은 [학년] [교과] 수석교사야.
#명령: 이 단원의 '바라는 결과'를 정해 줘.
#맥락
##근거: [기준] 지도서를 우선 근거로 하고, [맥락] 우리 반 실태를 참고해.
##조건: 성취기준은 코드와 문장을 지도서에 적힌 그대로 옮기고 인용 번호를 달아 줘.
#형식
① 단원 성취기준 ② 영속적 이해 2개(학생이 단원이 끝나도 기억할 큰 생각) ③ 본질적 질문 2개(정답이 하나가 아닌 질문) ④ 표(학생이 알아야 할 것 | 할 수 있어야 할 것)
```

### 소스 감사
id: ds-audit
meta: 설계 메모를 원본과 대조. 결과는 '확인할 목록'일 뿐 정답이 아닙니다

```
#역할: 너는 꼼꼼한 교육과정 검토위원이야.
#명령: '!'로 시작하는 메모 소스를 원본 '[지도서 파일 이름]'과 대조해서 감사해 줘.
#맥락
##점검 유형: ① 지도서와 어긋나는 내용 ② 지도서에 근거가 없는 내용(AI가 덧붙였을 가능성) ③ 지도서의 중요한 내용인데 메모에서 빠진 것 ④ 메모끼리 서로 다른 내용
##조건: 항목마다 해당 메모 이름과 지도서 인용을 함께 달아 줘. 문제가 없으면 '문제 없음'이라고 써 줘.
#형식: 표(점검 유형 | 메모 이름 | 내용 | 지도서 근거 | 조치 제안)로 정리하고, 끝에 '수업 설계 전에 고칠 것 3가지'를 적어 줘.
```
