### 설계 카드 ①: 성취기준·핵심질문·탐구질문 (차시 지정)
id: ds-card1
meta: 기존 '10가지 추출'을 한 차시·3장으로 묶은 개선판. 답을 메모 → 소스 → '![차시] 설계 카드①'
check: 성취기준 코드와 문장은 교육과정 원문과 대조하세요.
```
[N]차시에 대해서만 정리해 줘. 지도서 원문 표현을 그대로 쓰고 항목마다 인용 번호를 달아 줘. 지도서에 없으면 '지도서에 없음'.
① 성취기준(코드와 문장) ② 핵심질문 1개 ③ 탐구질문 3개 ④ 학습 목표
```

### 설계 카드 ②: 오개념·유의점·배움이 느린 학생
id: ds-card2
meta: 같은 차시로 이어서. 지도서 내용과 AI 제안을 구분
```
[N]차시에 대해서만 정리해 줘. 지도서 내용은 [지도서]+인용 번호, 네가 덧붙인 것은 [AI 제안]으로 구분해 줘.
① 학생 오개념과 교정 팁 ② 지도상 유의점·안전 수칙 ③ 선행학습이 부족한 학생이 어려워할 낱말·개념과 쉬운 비유 또는 예시
```

### 설계 카드 ③: 흐름·활동·평가
id: ds-card3
meta: 같은 차시로 이어서
```
[N]차시에 대해서만 정리해 줘. 지도서 표현을 쓰고 인용 번호를 달아 줘.
① 도입-전개-정리 흐름과 단계별 학생 행동 ↔ 교사 핵심 발문 ② 학생 중심 활동(실험·토의·게임)의 절차와 준비물 ③ 평가 방법과 상·중·하 기준 예시 ④ 마무리 확인 퀴즈 3문항
```

### 소스 감사
id: ds-audit
meta: 설계 메모를 원본과 대조. 결과는 '확인할 목록'일 뿐 정답이 아닙니다
check: 지적이 나오면 반드시 다음 '재검증' 프롬프트로 한 번 더 확인하세요. 연수 실습에서 지적 대부분이 오탐이었습니다.
```
#역할: 너는 꼼꼼한 교육과정 검토위원이야.
#명령: '!'로 시작하는 메모 소스를 원본 '[지도서 파일 이름]'과 대조해서 감사해 줘.
#맥락
##점검 유형: ① 지도서와 어긋나는 내용 ② 지도서에 근거가 없는 내용(AI가 덧붙였을 가능성) ③ 지도서의 중요한 내용인데 메모에서 빠진 것 ④ 메모끼리 서로 다른 내용
##조건: 항목마다 해당 메모 이름과 지도서 인용을 함께 달아 줘. 문제가 없으면 '문제 없음'이라고 써 줘.
#형식: 표(점검 유형 | 메모 이름 | 내용 | 지도서 근거 | 조치 제안)로 정리하고, 끝에 '수업 설계 전에 고칠 것 3가지'를 적어 줘.
```

### 재검증: 원문 그대로 인용
id: ds-verify
meta: 감사에서 나온 지적마다. 낱말 단위로 묻는 것이 가장 확실합니다
```
'[지도서 파일 이름]'에만 근거해서 답해 줘. ① '[지적된 낱말1]' ② '[지적된 낱말2]'라는 낱말이 나오는 부분을 각각 원문 그대로 인용해 줘. 없으면 '지도서에 없음'이라고만 써 줘.
```

### 여러 소스 압축하기
id: ds-compress
meta: 소스 50개 한도에 가까울 때. 결과를 메모 → 소스로 바꾸고 원본 일부는 체크를 끕니다
```
소스 [A], [B], [C], [D]의 공통점과 차이를 한 장으로 정리해 줘. 서로 다른 부분은 소스 이름을 밝혀 나란히 보여 주고, 각 문장에 인용 번호를 달아 줘.
```

### 소스 신뢰도·빈틈 점검
id: ds-gaps
meta: Fast·Deep Research로 가져온 웹 자료가 섞였을 때
```
지금 소스들을 신뢰도 순으로 나열하고 그 이유를 한 줄씩 적어 줘. 그리고 [단원/주제]를 가르치는 데 빠져 있는 관점이나 자료가 무엇인지 3가지 알려 줘. 교육과정 시기가 다른 자료가 있으면 표시해 줘.
```
