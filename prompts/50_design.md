### [확장] 웹 소스에서 사례 찾아 지도서와 잇기
id: ds-web-compare
meta: Fast Research로 고른 웹 소스 이름 앞에 [확장], 지도서 앞에 [기준]을 붙이고 둘을 체크한 뒤 보냅니다. 웹 소스에 본문이 일부만 들어온 경우 찾을 문단 이름을 적어 주세요
```
[확장] 소스의 '[문단 이름]' 문단까지 꼼꼼히 읽고, [주제]를 [학년]에게 설명할 때 쓸 수 있는 상황이나 장면 2가지를 찾아 줘. [확장] 소스 문장은 따옴표로 그대로 옮기고 인용 번호를 달아 줘. 그리고 각각이 지도서의 어느 설명과 이어지는지 지도서 인용 번호와 함께 연결해 줘.
형식: 표(사례 | [확장] 소스 문장 | [학년]용 쉬운 설명 | 이어지는 지도서 설명)
```

```
이 단원에서 학생들이 가장 어려워할 개념 3가지와, 지도서가 제시하는 지도 방법을 인용 번호와 함께 알려 줘. 그리고 [맥락] 소스의 우리 반 실태에 맞춰 지도 방법을 어떻게 조정할지 덧붙여 줘.
```

### 백워드 1단계: 바라는 결과
id: ds-ubd1
meta: 체크: [기준]·[맥락]. 답을 메모 → 소스로 바꾸고 이름 '[설계1] 바라는 결과'
check: 성취기준 코드와 문장을 인용 번호로 확인하세요.
```
#역할: 너는 백워드 설계(이해 중심 교육과정)에 밝은 [학년] [교과] 수석교사야.
#명령: 이 단원의 '바라는 결과'를 정해 줘.
#맥락
##근거: [기준] 지도서를 근거로 하고, [맥락] 우리 반 실태를 참고해.
##조건: 단원 성취기준을 코드와 문장 모두 지도서에 적힌 그대로 옮기고 인용 번호를 달아 줘. 영속적 이해와 본질적 질문은 단원 성취기준([성취기준 핵심어들])을 모두 아우르게 해 줘.
#형식
① 단원 성취기준 ② 영속적 이해 2개 ③ 본질적 질문 2개(정답이 하나가 아닌 질문) ④ 표(성취기준 코드 | 학생이 알아야 할 것 | 할 수 있어야 할 것)
```

### 백워드 2단계: 수행과제와 채점기준
id: ds-ubd2
meta: 체크: [기준]·[맥락]·[설계1]. 이름 '[설계2] 수행과제와 채점기준'
```
#명령: '[설계1] 바라는 결과'에 도달했는지 확인할 단원 수행과제를 만들어 줘.
#맥락
##수행과제 하나로 단원 성취기준([성취기준 코드들])을 모두 평가하게 해 줘. 하나의 결과물 안에 성취기준이 각각 한 부분씩 들어가게.
##GRASPS(목표·역할·청중·상황·결과물·기준)로 설계하고, 결과물은 [결과물 형태]로 해 줘.
##[맥락]에서 우리 반은 '[약한 능력]'이 약했으니 채점기준에 그 요소를 넣어 줘.
#형식
① GRASPS 표 ② 채점기준표(평가 요소 3개 × 잘함·보통·노력 필요, 요소마다 관련 성취기준 코드 표시, 학생이 이해할 쉬운 말) ③ 수준별 결과물 예시(각 2~3문장)
```

##각 차시가 [설계2] 결과물의 어느 부분을 준비하는지 '수행과제 준비' 칸에 적어 줘.

### 꼼꼼한 동료 교사 검토
id: ds-ubd-peer
meta: [설계1~3]을 체크한 뒤 보냅니다. '바로 고칠 3가지' 가운데 하나를 골라 반영한 수정판을 '(수정)'으로 저장하세요
```
#역할: 너는 백워드 설계 연수를 여러 번 진행한 꼼꼼한 동료 교사야.
#명령: '[설계1]', '[설계2]', '[설계3]'을 함께 보고 고칠 점을 찾아 줘.
#맥락
##점검 기준: ① 바라는 결과–수행과제–차시가 서로 이어지는가 ② 채점기준이 학생이 이해할 말로 쓰였는가 ③ 시간이 현실적인가 ④ 우리 반 실태를 반영했는가
##조건: 지적마다 근거가 되는 소스 문장을 인용 번호와 함께 달아 줘. 지도서에 있는지 확실하지 않은 내용은 지적하지 말고 '확인 필요'로 따로 모아 줘.
#형식: 표(점검 기준 | 고칠 점 | 근거 | 고칠 방법), 마지막에 '바로 고칠 3가지'
```

### 소스 감사
id: ds-audit
meta: 설계 메모를 원본과 대조. 결과는 '확인할 목록'일 뿐 정답이 아닙니다
check: 지적이 나오면 반드시 다음 '재검증' 프롬프트로 한 번 더 확인하세요. 실제 실행에서도 감사의 지적이 틀린 경우가 있었습니다.
```
#역할: 너는 꼼꼼한 교육과정 검토위원이야.
#명령: '!'로 시작하는 메모 소스를 원본 '[지도서 파일 이름]'과 대조해서 감사해 줘.
#맥락
##점검 유형: ① 지도서와 어긋나는 내용 ② 지도서에 근거가 없는 내용(AI가 덧붙였을 가능성) ③ 지도서의 중요한 내용인데 메모에서 빠진 것 ④ 메모끼리 서로 다른 내용
##조건: 항목마다 해당 메모 이름과 지도서 인용을 함께 달아 줘. 문제가 없으면 '문제 없음'이라고 써 줘.
#형식: 표(점검 유형 | 메모 이름 | 내용 | 지도서 근거 | 조치 제안)로 정리하고, 끝에 '수업 설계 전에 고칠 것 3가지'를 적어 줘.
```
